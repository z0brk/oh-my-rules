# 分流配置

## 业务入口

共 36 个组，其中 26 个可见，包括 8 个业务入口、9 个地区组、中转服务和末尾的 8 个独立手动组。业务入口的选项依次为默认出口、对应的手动组、地区组、`DIRECT`。开发交互的「亚洲自动」同时是默认出口，显示一次。

| 入口 | 初始选择 | 接管流量 |
| --- | --- | --- |
| 默认代理 | 默认自动，本机既有 AI自动 选择可沿用 | 普通海外服务与最终 MATCH |
| AI平台 | AI自动 | ChatGPT、Codex、Claude、Gemini、Copilot |
| 开发交互 | 亚洲自动 | GitHub 网页/API、开发登录、IDE 认证 |
| 文件下载 | 默认自动 | Git 传输、Release、Raw、工件仓库及工具更新 |
| 电报服务 | 默认代理 | Telegram 消息、图片、视频及原生附件。域名和已知 IP 段均匹配 |
| 推特服务 | 默认代理 | X/Twitter 网页、短链入口、图片和视频 |
| 谷歌服务 | 默认代理 | Google 通用域名和已知 Google IP |
| 微软服务 | 默认代理 | Microsoft 365、Outlook、OneDrive、微软通用账号登录 |

### 地区与固定节点

香港、日本、台湾、新加坡、韩国、美国、欧洲各有独立普通线路池。其他地区为这七个地区过滤条件的补集；亚洲自动另行覆盖全部已识别的亚洲线路。地区组采用 url-test，每 300 秒检测，容差 50 毫秒；空池使用 REJECT。各平台独立选择地区，在同一区域的自动池内可能换点。

地区组在 Sparkle 的「代理组」页独立显示。例如，先让电报服务选择日本节点，再展开「日本节点」点选具体节点。其他选择日本节点的业务也会使用这个地区组的选择。解除该组的固定选择即可恢复自动测速选优。

固定具体节点时，先在业务入口选它对应的手动组，再到列表末尾展开该组挑选。比如在「AI平台」选「AI手动」，再到「AI手动」选具体节点。各手动组独立保存选择，首项沿用业务的默认出口，第二项为 `DIRECT`。七个通用手动组可选全部真实节点，AI手动排除流量和免费节点。手动组选回首项即可恢复该业务的默认出口。

自建自动、落地服务、流量自动等进阶选项放在原有对应业务的手动组内。中转服务默认亚洲自动，只接普通线路及其地区池，保留落地节点引用中转的方向。

### 探测与故障回退

AI自动在 AI优选、AI备用之间按优先级回退，使用 OpenAI models 的 401 探测。优质自动在优质优选、优质备用之间回退，使用 GitHub robots.txt 的 200 探测。两类业务独立检测，每 60 秒主动探测；备用池里的可用性与账号、地区和各平台实际业务仍需分别验证。默认自动使用普通线路；流量自动只收带“流量”的节点。下载是否改用流量自动由该业务入口控制。

## 节点池

- `config.yml` 是本地源配置，不纳入 Git；保留本地实际默认订阅。
- `默认节点池` 接默认订阅，订阅本身直连获取以免启动时依赖尚未加载的节点。订阅转换器生成的顶层 `proxies` 也会作为默认候选，但排除流量和落地节点。
- `优质节点池` 可放明确认可的优质节点。优质优选和 AI优选从全部 provider、顶层节点收取名称含“优质”的节点，排除流量节点；可通过订阅处理器或 `additional-prefix` 添加标记。家宽、美西 DMIT 使用“优质”标记。
- `流量节点池` 可接免费、低倍率或其他适合传输的订阅。流量节点名称必须包含“流量”。
- 流量自动按名称从顶层 `proxies` 和所有 provider 收集流量节点，支持平铺或合并订阅；不收取未标记节点，不自动借用普通默认节点。
- 默认普通池、中转和地区池排除流量、落地节点。AI 和开发自动池分别使用自己的优选/备用筛选。
- 未接入的池用显式 `reject` 节点占位，筛选为空时也回退到 `REJECT`，不会意外直连。

公开模板保留三个同名节点池，但清除本地 provider 的订阅链接及节点凭据。
接入新订阅时，将相应池改为 `type: http` 并填写 URL；优质、流量 provider 的更新可指定 `proxy: 默认代理`。
可使用独立 provider，也可交给现有订阅转换器合并；合并后必须保留每个流量节点名称中的“流量”标记。
Sub-Store 中连连看、论坛白嫖使用“流量”订阅标签和节点名前缀，家宽、美西 DMIT 使用“优质”标签和前缀；原有处理链保留。源订阅是否进入客户端仍取决于聚合成员，不自动调整集合成员。
通过 Sub-Store API 局部更新订阅时须显式携带原 `name`；只发送 `process`、`tag` 会导致部分旧版后端改写聚合引用。

## 列表与优先级

1. `block.list`、`ads.list` 和公共 Tracker 拦截。
2. 内网、NTP 和 `direct.list`。随后匹配电报服务（Telegram 域名和已知 IP 段）、推特服务（Twitter/X 域名），再处理直连进程。
3. `ai.list` 的 AI 专属例外。
4. `traffic.list` 的 Git 传输与专用文件域名。
5. `proxy.list` 的个人代理例外，再由上游 AI 分类和 `GEOSITE,github` 识别专属业务。
6. MetaCubeX 的 `microsoft.mrs` 和 `google.mrs` 分别进入微软服务、谷歌服务。Google 搜索、Gmail、Maps、字体以及 Microsoft 365、Outlook、微软账号登录均按厂商分流。
7. `quality.list` 补开发认证和第三方共享域名；AI Suite 补 AI 端点与语音 IP；已知 Google IP 进入谷歌服务（`no-resolve`）。
8. 国内直连和旧下载器直连，最后是海外与 IP 兜底。

谷歌服务、微软服务、电报服务和推特服务首次均跟随默认代理。谷歌与微软分别保存出口，远程 MRS 每 24 小时更新。通用厂商域名由上游维护，Gemini/Copilot、GitHub 和专用下载等更具体的业务先匹配。

电报和推特继续单独分流。两个组各自保存选择，可以给电报选亚洲自动，同时给 X 固定一个美国节点。Telegram 的 IP 规则使用 `no-resolve`。X 使用较窄的 `GEOSITE,twitter`，覆盖短链和媒体域名；Grok 与 xAI 独立域名继续按后续规则匹配。第三方外链按实际目标分流。

GitHub 网页、登录、Issues、PR 和普通 API 属于开发交互；Git/LFS 与 GitHub 目标匹配时进入文件下载。
Release、Raw、源码归档、LFS 对象等专用文件域名也进入文件下载。HTTPS 共用域名上的浏览器/API 文件响应不能按路径精确区分。
保留旧 Download 列表的直连行为和现有 Tracker 拦截，不把全部下载器或 BT/PT 自动送入流量池。
保留 AI Suite 的语音 IP 和其他补充，先用本地精确规则处理共享域名冲突。

`direct.list` 中 rayae、z0brk、ngcdc 的既有关键词尚未确认完整域名，暂不猜测后缀或删除。

## 生成与验证

```sh
./update.sh --generate-only
ruby tests/check_config.rb
python3 tests/check_failover.py /path/to/mihomo
mihomo -t -d /path/to/isolated-check-directory -f config-template.yml
```

`--generate-only` 只生成本地镜像和两个公开模板，不暂存、提交或推送。
不带参数的 `update.sh` 仍是原发布流程，会提交、改写历史并强制推送，勿用于普通验证。
Mihomo 校验应使用独立目录，必要时准备 geodata 和规则缓存，不使用 Sparkle 工作目录作为测试目录。

### Sparkle 迁移

手动刷新使用本仓库模板的订阅后，检查个人覆写中的策略目标和已选出口。以前直接固定在业务入口里的节点，现在从对应的手动组重新选择。旧分组优质服务、流量服务、亚洲节点分别对应开发交互、文件下载、亚洲自动。中转服务原选亚洲节点时由新的首选亚洲自动承接。旧亚洲池曾手动指定的具体节点需要单独迁移。

公开模板的三个节点池是无凭据占位。不要单独用它们替换正在使用的订阅。本地验证优先用独立测试目录及规则快照。
