# 分流配置

## 用途与策略

共 19 个分组，其中 11 个可见，8 个底层自动组设置 `hidden: true`。可见名称统一为四个字符；AI平台保留惯用英文缩写，不用空格补齐宽度。

四个用途组共享相同分组选项：AI自动、优质自动、默认自动、流量自动、自建自动、落地服务、亚洲节点、美洲节点、欧洲节点、其他地区。各组把默认策略放第一位，不互相引用用途组。

AI平台、优质服务只直接列出非流量、非免费具体节点，排除名称含“流量”“免费”或 `free`（不区分大小写）的节点；仍可主动选择流量自动等分组策略。流量服务、默认代理保留全部真实代理节点（包括流量和落地），不改变其手动选择范围。流量服务只是默认使用流量自动，并不限制手动选择。筛选依据节点名称标记。

AI自动、优质自动使用 `fallback`，只在各自的优选池和备用池之间切换：优选池全部失败后使用备用池，优选恢复后自动优先使用。两个池内部均使用 `url-test`，按业务检测延迟选优，延迟容差保持 50 毫秒；不再按订阅顺序固定选择第一个普通节点。备用池沿用用途组的非流量、非免费筛选，并排除“优质”标记，避免与优选池重复；不通过默认自动或地区组的普通测速判断 AI 可用性。这两个故障转移组及其优选、备用组均每 60 秒主动检测，不因暂时无流量而停测。其余自动组保持 `url-test`、每 300 秒检测、延迟容差 50 毫秒，节点范围不变。隐藏分组只隐藏独立卡片，界面是否遵循 `hidden` 取决于客户端。

日常在用途组里选择自动池、地区组或具体节点。AI平台选 AI自动、优质服务选优质自动时启用故障转移；手动选择其他分组或具体节点时不强行改选。用途组直接选择具体节点是固定出口，失效后不会自动换点。可见的自建、落地、地区自动组仍可在组内手动指定节点，指定节点在该组检测 URL 下可用时优先使用，不可用时仍在本池内自动选择。故障检测和切换不是即时的，也不保证现有连接无缝迁移。

中转服务可选自建自动（默认）、默认自动、亚洲节点、美洲节点、欧洲节点、其他地区，以及默认池中的具体节点。排除流量、落地节点和可能引用落地的用途/优质组，保留已有落地节点上的 `dialer-proxy: 中转服务`，避免回环。

各业务使用专门的检测 URL；故障转移组和其优选、备用组使用相同地址及状态要求。检测是连通性检查，不代表带宽、所有业务或账号权限正常；AI检测要求返回 401，403 等响应不会作为可用，但 401 也不代表账号已授权或其他 AI 平台一定可用。镜像版仍直接检测 GitHub，不检测镜像站。只有 AI自动、优质自动会在优质池故障后自动使用普通候选，自建、落地、地区及流量自动组不跨池。

## 节点池

- `config.yml` 是本地源配置，不纳入 Git；保留本地实际默认订阅。
- `默认节点池` 接默认订阅，订阅本身直连获取以免启动时依赖尚未加载的节点。订阅转换器生成的顶层 `proxies` 也会作为默认候选，但排除流量和落地节点。
- `优质节点池` 可放明确认可的优质节点。优质优选和 AI优选从全部 provider、顶层节点收取名称含“优质”的节点，排除流量节点；可通过订阅处理器或 `additional-prefix` 添加标记。家宽、美西 DMIT 使用“优质”标记。
- `流量节点池` 可接免费、低倍率或其他适合传输的订阅。流量节点名称必须包含“流量”。
- 流量自动按名称从顶层 `proxies` 和所有 provider 收集流量节点，支持平铺或合并订阅；不收取未标记节点，不自动借用普通默认节点。
- 默认、优质、AI、自建、地区、落地自动池和中转候选排除名称含“流量”的节点。四个用途组均可手动选择流量组，但只有流量服务、默认代理直接列出流量或免费具体节点。订阅载入层不屏蔽这些节点，剩余流量、到期等提示仍过滤。
- 未接入的池用显式 `reject` 节点占位，筛选为空时也回退到 `REJECT`，不会意外直连。

公开模板保留三个同名节点池，但清除本地 provider 的订阅链接及节点凭据。
接入新订阅时，将相应池改为 `type: http` 并填写 URL；优质、流量 provider 的更新可指定 `proxy: 默认代理`。
可使用独立 provider，也可交给现有订阅转换器合并；合并后必须保留每个流量节点名称中的“流量”标记。
Sub-Store 中连连看、论坛白嫖使用“流量”订阅标签和节点名前缀，家宽、美西 DMIT 使用“优质”标签和前缀；原有处理链保留。源订阅是否进入客户端仍取决于聚合成员，不自动调整集合成员。
通过 Sub-Store API 局部更新订阅时须显式携带原 `name`；只发送 `process`、`tag` 会导致部分旧版后端改写聚合引用。

## 列表与优先级

1. `block.list`、`ads.list` 和公共 Tracker 拦截。
2. 内网、NTP、`direct.list` 及明确直连进程。
3. `ai.list` 的 AI 专属例外。
4. `traffic.list` 的 Git 传输与专用文件域名。
5. `quality.list` 的普通 GitHub API、共享登录和 Google 通用服务例外。
6. `proxy.list` 的默认代理例外。
7. 外部 AI Suite、AI 分类，再到 Microsoft、Google 优质服务。
8. 国内直连和旧下载器直连，最后是海外与 IP 兜底。

GitHub 网页、登录、Issues、PR 和普通 API 属于优质服务；Git/LFS 与 GitHub 目标匹配时进入流量服务。
Release、Raw、源码归档、LFS 对象等专用文件域名也进入流量服务。HTTPS 共用域名上的浏览器/API 文件响应不能按路径精确区分。
保留旧 Download 列表的直连行为和现有 Tracker 拦截，不把全部下载器或 BT/PT 自动送入流量池。
保留 AI Suite 的语音 IP 和其他补充，先用本地精确规则处理共享域名冲突。

`direct.list` 中 rayae、z0brk、ngcdc 的既有关键词尚未确认完整域名，暂不猜测后缀或删除。

## 生成与验证

```sh
./update.sh --generate-only
ruby tests/check_config.rb
python3 tests/check_failover.py /path/to/mihomo
mihomo -t -d /path/to/isolated-check-directory -f config-template.yml
```

`--generate-only` 只生成本地镜像和两个公开模板，不暂存、提交或推送。
不带参数的 `update.sh` 仍是原发布流程，会提交、改写历史并强制推送，勿用于普通验证。
Mihomo 校验应使用独立目录，必要时准备 geodata 和规则缓存，不使用 Sparkle 工作目录作为测试目录。

新增列表未发布前，其远程 URL 不可依赖；本地校验应指向仓库列表和外部规则快照。
切换 Sparkle 前还需同步其独立覆写中的旧组名（例如 `美国策略`）。本仓库的生成和检查不会修改或切换 Sparkle。
